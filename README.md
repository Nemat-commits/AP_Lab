# PC Builder & Hardware Compatibility Checker

## 1. The project in plain language

This is an offline Windows desktop workbench for planning a PC in Pakistani rupees. Choose a CPU, motherboard, graphics card, memory, storage, power supply, case and CPU cooler. The status banner and diagnostics update as you work. A blank slot is not treated as a failure, so a green banner on a partial build does not mean the build is complete. The power estimate includes CPU and GPU plus 60 W for the rest of the system, and recommends 30% extra capacity.

The catalog contains at least 20 options for each of the eight categories. Specifications and prices are illustrative, not live market quotes; exact GPU dimensions, cooler socket support, and other details vary by retail model and revision. Type a local price in a slot to override the catalog price; clear that field to return to the catalog price. Use the cross to clear a slot, or **Clear all** to reset all selected parts, prices, filters and the target budget after confirmation. Saved builds and custom catalog parts are not deleted. Expand **Filter parts** to narrow the part dropdowns by search, brand, socket or maximum price; already selected parts remain visible. Add a custom part by providing its specifications. Custom parts are kept locally and are available in future sessions. Save and load JSON to keep complete builds and price overrides; back up those files and the custom parts file yourself. No online services are used.

To generate a starting build, enter a target in the Budget Builder and choose **Generate compatible build**. The app samples compatible eight-part combinations using catalog and custom-part prices, preferring totals closest to the target; it shows whether the result is within 10% or the closest sampled result outside that range. The search runs in the background; confirm before it replaces a current build. If you edit your build or target during the search, the stale result is discarded. Results are a starting point, not an optimized performance recommendation.

Checks cover socket, RAM generation and limits, RAM speed, motherboard and GPU fit, cooler fit and cooling capacity, storage ports, and PSU capacity. They are simplified planning checks, not guarantees of physical fit or manufacturer support. Verify specifications, BIOS compatibility and real-world prices before buying.

## 2. Technical guide and implementation

- **Requirements:** Windows with .NET 8 SDK (or .NET 8 desktop runtime for a published application). WPF runs on Windows only.
- **Download and run:** The successful Windows GitHub Actions run includes a `PCBuilder-Windows-x64` artifact. Download it, extract the ZIP, and run `PCBuilder.Desktop.exe` on 64-bit Windows. Keep the included `Data` folder alongside the executable. This self-contained package does not require installing .NET; it is unsigned and Windows may show a SmartScreen warning. GitHub Actions artifacts expire, so retain your own backup.
- **Run from source:** `dotnet run --project PCBuilder.Desktop.csproj` from the repository root. Build with `dotnet build PCBuilder.Desktop.csproj`. Run the cross-platform domain tests with `dotnet run --project Tests/PCBuilder.Tests.csproj` and the Windows WPF smoke test with `dotnet run --project SmokeTests/PCBuilder.SmokeTests.csproj`.
- **Layers:** `Domain/Models.cs` contains the polymorphic component hierarchy and `PCBuild`; `Services/CompatibilityChecker.cs` implements R-01–R-10; `Services/BudgetBuildService.cs` samples complete compatible combinations; `Services/CatalogService.cs` handles JSON and LINQ; `ViewModels/` manages state and commands; `MainWindow.xaml`, `Views/` and `Themes/` provide WPF presentation.
- **Persistence:** `Data/hardware_catalog.json` is copied to the output directory. User-created parts are stored at `%LOCALAPPDATA%\PCBuilder\custom_parts.json`; builds are explicitly saved wherever the user chooses. These user files are not automatically backed up to Drive. Build and custom catalog saves use a temporary file and replacement to reduce the risk of a partial write. Invalid component values in saved files are rejected rather than applied. Build JSON contains full component data and optional `CustomPricePKR`. Catalog choices are cloned so per-build overrides do not mutate the seed catalog.
- **Rules:** R-01 socket; R-02 RAM type; R-03 DIMM/capacity; R-04 RAM speed advisory; R-05 motherboard form factor; R-06 GPU length; R-07 cooler height/socket; R-08 cooler TDP advisory; R-09 storage ports; R-10 PSU tier. Missing inputs skip their corresponding checks. Power is zero until a CPU or GPU is selected; otherwise `CPU TDP + GPU TDP + 60`, with `ceil(estimate * 1.30)` recommended. This resolves a contradiction in the specification in favour of its prose rather than its sample code (which adds 60 W for any selected component).
- **Budget algorithm:** A deterministic, bounded search samples 2,500 combinations, checks the ten rules incrementally, excludes both errors and warnings, and returns the closest sampled total (ties prefer the one below budget). It ignores UI filters, includes saved custom catalog parts, and uses catalog/custom part prices, not overrides from the previous build. It does not guarantee a global optimum or benchmark performance. If no compatible sample is found, the current build is retained.
- **Scope and assumptions:** The catalog contains sample AM4, AM5 and Intel parts; prices/specifications should be verified. Custom fields are entered using invariant numeric notation, list fields use commas, and storage type must be NVMe or SATA. There is no network integration, PDF export, liquid-loop validation, or bottleneck calculator. Prices are limited to PKR 0–1,000,000,000 per part; invalid price input is flagged and the total is withheld until corrected. A GitHub Actions Windows job builds the WPF project, opens the window for selection/filter/pricing smoke checks, and runs the domain checks; a manual visual and end-to-end Windows UI review is still recommended before release.
